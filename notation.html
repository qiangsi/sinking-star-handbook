第 三 章

读谱 · 箭头、次数与动作代码

社区解法是一串紧凑的字母与数字。这章把每个记号拆开讲， 再说清自动求解记录里两个特殊符号的来历——读懂了再动手，比抄快得多。

记号总表

↑
U · 向上字母 U 即「上」方向的移动
↓
D · 向下字母 D 即「下」方向的移动
←
L · 向左字母 L 即「左」方向的移动
→
R · 向右字母 R 即「右」方向的移动
×n
数字 · 重复次数紧跟字母后的数字表示连续执行几次，如 R2 = → ×2
X
X · 主要行动推动、互动等核心动作，以游戏内实际按键为准
C
C · 切换角色把操作权换给另一位可操作角色
V
V · 次要行动次要动作键，同样以游戏内绑定为准
F / B
疑似「前 / 后」仅见于自动求解记录，含义未证实，见下文

键位提示：社区播放器按 WASD / 方向键回放方向移动，X、C、V 对应同名键位； 播放器里 Z 是撤销、R 是重置。你在游戏里完全可以自定义按键—— 谱上的字母只表示「方向」与「动作类型」，不锁定你的键位。

读一条真实的谱

以镜像群岛的第一关为例，社区数据里的原始记录是 R2XL4XL6U。 按记号展开，一共六步：

右R×2 主行动X 左L×4 主行动X 左L×6 上U

用人话说：向右走两格，执行一次主行动；向左回四格，再来一次主行动； 继续向左六格，最后向上一步收尾。金色是移动、青色是行动按键、红色是存疑记号； 鼠标悬停可看每个记号的完整说明。方向是棋盘视角的方向—— 建议先把镜头摆正、和截图对齐，再按谱走，镜头一歪，左右就全反了。

关于 F / B：一个诚实的存疑

翻开本手册索引里的自动求解记录，你会在少数序列中看到 F 与 B 两个字母。 本手册核对过社区播放器的源码：它的键位表里只有 U、D、L、R、X、C、V， 遇到 F、B 会直接跳过并给出警告。社区玩家录制的路线里，也从未出现过这两个字母。

也就是说：F / B 只存在于程序求解的输出里，很可能是求解器对某种特殊局面 （比如三维关卡的前后轴，或引擎内部的特殊步）的编码，但目前没有权威解释。 本手册不做臆断，只给三条实用建议：

  1. 含 F / B 的序列，优先到社区地图上找同关的玩家路线或视频替代；
  2. 若只能用自动序列，把它当作「思路参考」而不是「操作清单」——跳过 F / B 逐步试；
  3. 试出来了？欢迎把结论带回社区（joric/ootss 的仓库 Issue 区），让下一个玩家少走弯路。

三条使用心法

① 分段验证，不要一口气抄完

把长序列按 5–8 步切一段，走一段、看局面：角色到位了吗？机关响应了吗？ 一旦对不上，立刻停在原地找原因，别用撤销把进度全冲掉。

② 先理解，再复刻

每段问自己一句「这几步在干什么」——是把石头顶到转角，还是把光束借镜子折过去？ 理解了意图，中途出偏差时你才知道怎么补救；纯抄谱，一步错就全盘乱。

③ 谱是路标，不是代打

自动求解的步数未必最优，社区路线也可能有更优雅的替代。 走通之后不妨回头看看：有没有更短的路径？那才是这游戏真正的乐趣所在。

读谱之后

规则都在手上了，去索引里找到你那一关，把它走通吧。
